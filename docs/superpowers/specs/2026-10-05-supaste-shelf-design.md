# Pengrid 상단 보관함 설계

상태: 기능 범위 확정, 상세 설계 검토 대기. 제품 코드는 아직 구현하지 않았다.

## 목적과 확정 범위

사용자는 Pengrid에 Supaste를 참고한 상단 노치형 UI를 추가하고, 첫 범위로 **파일·텍스트·이미지 수동 보관 + 검색 + 작업 진행률**을 선택했다. 텍스트·이미지 클립보드 지원도 별도로 명시했다.

성공 기준은 다른 앱과 Pengrid 사이에서 항목을 잠시 모아 다시 사용하는 것이다. 파일 관리자를 별도 클립보드 앱으로 교체하거나, 사용자의 모든 복사 내용을 자동 수집하는 것이 아니다.

## 접근 방식

- **권장: Pengrid가 소유하는 보조 패널 하나.** 기존 파일 작업 상태와 설정을 공유한다. AppKit은 창·pasteboard·drag 경계만 담당하고, SwiftUI가 보관함 UI를 표시한다. 추가 패키지나 별도 백그라운드 프로세스는 없다.
- 별도 helper 앱은 Pengrid 종료 후에도 사용할 수 있으나 IPC·설치·종료 수명 관리가 추가된다. 이번 요구에는 선택하지 않는다.
- 메뉴 막대 팝오버만 사용하는 방식은 사용자가 요청한 상단 노치형 보관함을 충족하지 않으므로 대안으로 대체하지 않는다.

## 사용자 동작

1. 설정의 `Top Shelf`는 기본 OFF다. 사용자가 활성화하면 상단의 작은 보관함 손잡이가 나타난다. 앱 메뉴에서도 표시·숨기기를 제어한다.
2. 손잡이를 클릭하면 보관함이 펼쳐진다. 파일을 패널에 놓거나 `Add from Clipboard`를 눌러 현재 파일·텍스트·이미지를 추가한다. 표시·hover·검색·진행률 갱신만으로 클립보드를 읽지 않는다.
3. 항목에는 종류, 이름 또는 짧은 텍스트, 이미지 미리보기를 표시한다. 검색창과 `All / Files / Text / Images` 필터를 제공한다.
4. 항목의 `Copy`는 보관함 수명과 독립적인 데이터를 클립보드에 쓰고, 쓰기 결과를 확인한다. 실패하면 오류를 표시하고 보관 항목은 유지한다. Clear/OFF/앱 종료는 이미 기록한 시스템 클립보드를 지우지 않는다. drag-out은 파일 URL, 문자열, 이미지의 native 타입을 제공하며 copy-only다. 붙여넣기 키를 다른 앱에 자동 전송하지 않는다.
5. `Remove`와 `Clear`는 보관함 항목만 제거한다. 원본 파일을 이동·삭제하거나 실행하지 않는다. 패널 숨김은 항목을 유지한다.
6. 기존 작업의 진행률과 대기·실패·복구 필요 상태를 읽기 전용으로 표시한다. `Open Pengrid`로 기존 주창에 돌아가 충돌·암호·취소를 처리한다. 보관함 닫기가 파일 작업을 중단하지 않는다.

## 보관과 가져오기 계약

- 첫 버전은 **앱 실행 중 메모리 보관**이다. 정상 종료·재실행 후에는 보관함에 항목이 남지 않는다. 사용자가 Copy로 내보낸 시스템 클립보드와 다른 앱의 복사본은 별개다. 이 제한을 패널 안내와 문서에 명시한다. 설정의 ON/OFF 값만 UserDefaults에 저장한다.
- OFF 전환은 창을 숨기고 보관 항목을 비운다. 선택한 항목·검색어도 지운다. 파일 참조와 미리보기만 해제하며 원본에는 쓰지 않는다.
- 한 번의 입력에서 파일 URL이 있으면 파일로, 그렇지 않으면 이미지, 마지막으로 문자열로 해석한다. 이미지의 보조 문자열 표현을 별도 텍스트로 중복 수입하지 않는다. 모든 입력이 검증되기 전에는 기존 목록을 바꾸지 않는다.
- 버튼을 누른 시점의 pasteboard `changeCount`를 기록하고 타입·concealed/transient 표시·payload를 같은 세대에서 읽는다. 대기 또는 읽기 도중 세대가 바뀌면 가져오기를 거부하고, 바뀐 내용을 자동 재시도하지 않는다.
- 파일은 로컬 file URL 참조만 보관한다. 폴더도 가능하다. 내용을 읽거나 cloud placeholder를 자동 다운로드하지 않는다. 외부에서 파일이 이동·삭제되면 사용 시 오류를 표시하고 참조 제거를 안내한다.
- 텍스트는 plain text, 이미지는 PNG/TIFF로 들어온 bitmap만 받는다. HTML/RTF/SVG 실행·렌더링, URL 미리보기, file promise 수입은 이번 범위에 없다. URI처럼 보이는 문자열도 네트워크에 접근하지 않는다.
- 최초 한도는 항목 50개, 텍스트 항목당 UTF-8 256KiB, 이미지 입력당 16MiB·최대 40메가픽셀, 보관 payload 합계 64MiB다. 16MiB/64MiB는 인코딩 데이터 기준이며 앱 전체 메모리 상한을 뜻하지 않는다. 한도 초과·잘못된 이미지·혼합된 유효/무효 파일 URL 입력은 명시적으로 거부하며 기존 항목을 자동 퇴출하지 않는다.
- 이미지 메타데이터로 픽셀 수를 먼저 검사하고, 전체 크기 디코딩 버퍼를 상시 보관하지 않는다. ImageIO downsampling으로 최대 변 256px의 RGBA8 썸네일을 하나씩 생성한다. 보관하는 썸네일 픽셀 버퍼는 항목당 최대 256KiB이며, 프레임워크 내부의 일시적 할당까지 일정한 RSS라고 주장하지 않는다.
- 비동기 수입은 하나씩 처리한다. 읽는 동안 Clear/OFF가 실행되면 이전 수입 결과를 버려 항목이 다시 나타나지 않게 한다.
- 파일 URL의 완전 동일 중복은 추가하지 않는다. 텍스트·이미지는 사용자가 수동 추가한 각각의 항목으로 다룬다. 대규모 해시·유사도 중복 검사는 넣지 않는다.
- 알려진 concealed/transient pasteboard 표시가 있으면 저장을 거부한다. 이 검사는 일반 문자열의 비밀 정보를 모두 탐지하지 못한다. 실제 클립보드 내용·전체 파일 경로·텍스트 본문을 로그에 기록하지 않는다.
- 파일·텍스트·이미지의 Copy는 명시적 사용자 동작이다. 테스트에는 고유 이름의 NSPasteboard를 주입하고 시스템 클립보드를 덮어쓰지 않는다.

## 검색

파일명, 텍스트 본문, 이미지 표시 이름을 검색한다. 파일 내용·OCR·원본 폴더 전체 탐색은 하지 않는다. 빈 검색은 모든 항목을 보인다. 기존 `SmartSearchTextAnalyzer`의 대소문자 정규화·한글 초성 동작을 재사용하고, 검색어가 구두점뿐인 경우에는 문자 그대로 비교한다.

목록 수입 시 검색용 값을 준비하고, 텍스트 본문 검색은 주 스레드에서 반복하지 않는다. 검색 갱신은 취소 가능하게 처리하며 최신 검색어에 해당하는 결과만 반영한다. 이미지 OCR은 현재 선택 범위 밖이며 별도 후속 기능이다.

## 창 배치·키보드·접근성

- 앱 수명에 패널 하나만 둔다. `WindowGroup`별로 생성하지 않는다. 보관함은 주창이 아닌 보조 창이다.
- 노치 아래쪽 안전 영역에 붙는 검은 pill 형태로 표시한다. 버튼과 검색창은 카메라 영역 및 메뉴 막대를 침범하지 않는다. 노치 없는 화면에서도 상단 중앙 pill로 동작한다.
- 사용자가 표시한 시점의 Pengrid 주창 화면을 사용하고, 없으면 기본 화면을 사용한다. `NSScreen.visibleFrame`·`safeAreaInsets`를 사용해 위치를 제한하고 디스플레이 분리·배율 변경 시 다시 계산한다. 모든 화면에 패널을 복제하지 않는다.
- 대기 상태·진행률 갱신·마우스 접근이 다른 앱의 키 입력 포커스를 빼앗지 않는다. 키보드 입력은 사용자가 패널을 명시적으로 선택할 때만 받는다. 시스템 보안 화면 위로 강제 표시하지 않는다.
- Escape/닫기는 패널만 닫는다. 패널의 Delete는 보관함 항목 또는 편집 중인 텍스트에만 작용한다. `⌘W`, `⌘Delete`, `⌘V`가 뒤쪽 workspace 탭·파일 명령으로 전달되지 않도록 별도 창 소유권을 확인한다.
- 기존 충돌·암호·이름 변경 modal이 활성화되어 있으면 보관함 상호작용으로 이를 가로채지 않는다. 보관함은 `worksWhenModal`을 켜지 않는다.
- 키보드로 표시·닫기·검색·Copy·Remove·Clear를 조작할 수 있어야 한다. 안정적인 접근성 identifier와 읽을 수 있는 항목/상태 label을 제공하고 Reduce Motion을 존중한다.

## 기존 코드 연결

- `BloomFileManagerApp`에서 store/controller를 앱 소유로 구성하고 기존 Settings와 Commands에 진입점을 둔다.
- `FolderPreviewController`·`GetInfoInspectorController`의 panel 수명 패턴을 참고하되 자동 표시의 `makeKeyAndOrderFront`는 가져오지 않는다.
- `FileURLPasteboard`의 읽기와 기존 file URL 검증 경계를 재사용한다. 기존 쓰기 helper는 반환값을 무시하므로 성공 여부를 확인할 수 있게 필요한 경계만 보완한다. 여러 폴더 항목을 보관하는 목록을 단일 workspace에 묶인 `FileContextActionRouter`로 처리하지 않는다.
- `FileOperationController.activeJob/queuedJobs/isQueueBlockedByRecovery`와 `FileOperationCenterProgressPresentation`을 관찰한다. 별도 polling/event bus/작업 엔진을 추가하지 않는다. 알 수 없는 총량·encoding·암호 대기는 불확정 표시로 유지한다.
- 새 코드는 보관 상태, 수동 입력 변환, 패널/화면의 세 책임으로 구분한다. 작은 화면 배치 함수는 실제로 경계 테스트가 필요할 때만 분리한다. 공용 추상화 프레임워크를 추가하지 않는다.

## 검증과 배포 기준

- Store/입력: 세 종류, 우선순위, 잘못된 혼합 입력, 인코딩/썸네일 한도, 이미지 decode 실패, pasteboard 세대 변경, Clear/OFF와 진행 중 수입 경합, 파일 중복, 원본 불변.
- 검색: 한글 초성·대소문자·구두점·빈 검색·필터·취소 후 최신 결과. 본문 수입/검색으로 UI가 장시간 막히지 않는지 확인.
- 패널: 재사용/ON-OFF, 화면 좌표 음수·작은 외장 화면·노치 안전 영역, Escape와 중복 종료 방지, 접근성 identifier.
- 실제 키 라우팅: 주창에서 파일을 선택한 상태로 보관함의 검색/항목에 포커스를 두고 `⌘W`, Delete, `⌘Delete`, `⌘V`, Escape를 실행해 주창의 파일·탭·작업이 바뀌지 않음을 확인. modal과 함께 검사한다.
- Drag/Copy: named pasteboard로 파일·텍스트·이미지 표현, 쓰기 실패, 보관함 삭제 후 Copy 데이터의 수명을 검사하고, 실제 앱 사이 drag 성공·취소를 합성 fixture로 확인한다. native 텍스트/이미지를 받지 않는 대상에는 파일 export를 지원한다고 주장하지 않는다.
- 기존 `DropIntentTests.copyAndPasteDispatchToAnActualNSTextResponder`는 시스템 클립보드를 직접 바꾼다. 로컬 전체 회귀 검사 전 이 테스트의 pasteboard 의존성을 격리하거나 독립된 테스트 사용자 환경에서 실행한다. 사용자의 현재 클립보드를 읽어 백업하는 방식으로 우회하지 않는다.
- 진행: 기존 항목 단위/바이트 단위/불확정/암호/복구 상태 표시를 유지하고 패널을 닫아도 작업이 지속됨을 확인한다.
- 관련 테스트 후 회귀 검사와 앱 번들/패키지 계약 검사, 영어·한국어 사용 설명서를 갱신한다. UI 확인이 불가능하면 그 제한을 명시하고 완료로 간주하지 않는다.
- 기능별 커밋·푸시는 매번 Ponytail review gate를 통과한다. CI 통과 후 GitHub main에 병합하고, 병합/복구 증거가 있는 해당 임시 worktree와 생성물만 정리한다. 설치 앱·기존 WIP·사용자 데이터는 제외한다.

## 참고 자료와 경계

- [Supaste](https://www.supaste.com/): 노치 보관함과 검색 가능한 여러 타입의 클립보드 사용 흐름을 참고했다. 상표·이미지·소스는 복제하지 않는다.
- [Supaste 개인정보 정책](https://www.supaste.com/privacy): 수동 수집과 로컬 저장/사용자 제어 참고. 홈페이지의 iCloud 홍보와 정책의 cloud sync 설명이 일치하지 않아 동기화 동작을 검증된 사실로 채택하지 않는다.
- [Ledge](https://github.com/marcotteink/ledge): 원본을 유지하는 copy-only 보관함과 수동 클립보드 가져오기 흐름 참고. 외부 코드를 도입하지 않는다.
- [Apple NSPanel](https://developer.apple.com/documentation/appkit/nspanel) 및 [화면 안전 영역](https://developer.apple.com/documentation/appkit/nsscreen/auxiliarytopleftarea-uglc): 보조 창과 화면 배치의 공개 API 경계.

자동 클립보드 기록, 재시작 후 영구 히스토리, OCR, 다른 앱으로 키 입력 주입, iCloud/외부 동기화, AI 변환은 첫 범위에 포함하지 않는다. 선택 범위를 확장할 경우 저장·권한·보안 계약을 별도로 검토한다.
