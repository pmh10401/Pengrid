# Pengrid 상세 기능 안내서

**한국어** · [English](user-guide.md) · [README](../README.ko.md)

이 문서는 Pengrid 1.3.0 Developer Preview 5와 현재 소스 트리에 완성된 기능의
사용자 관점 동작, 안전 경계와 의도적으로 제공하지 않는 기능을 설명합니다.
**현재 소스 빌드**라고 표시한 기능은 이후 릴리스를 패키징하기 전까지 공개된
Preview 5 DMG에는 포함되지 않습니다.

## 요구 사항과 설치

현재 Pengrid는 macOS 15 이상이 설치된 Apple Silicon Mac을 지원합니다.
[Developer Preview 5 릴리스](https://github.com/pmh10401/Pengrid/releases/tag/v1.3.0-developer-preview.5)에서
DMG를 다운로드해 열고 `Pengrid.app`을 `Applications` 폴더로 복사하세요.

무료 DMG는 ad-hoc 방식으로 서명되었으며 Developer ID 서명과 Apple 공증을
받지 않았습니다. 따라서 Gatekeeper가 실행을 차단할 수 있습니다. Pengrid는
macOS 보안 기능을 비활성화하라고 안내하지 않습니다. 파일 검증과 로컬 빌드
방법은 [릴리스 안내서](release.ko.md)를 참고하세요.

## 듀얼 패널 작업 공간

Pengrid는 두 파일 패널을 동시에 표시합니다. 패널을 클릭하거나 그 안에서
탐색하면 해당 패널이 활성화됩니다. 명령 이름에 왼쪽에서 오른쪽 또는 오른쪽에서
왼쪽 방향이 명시되어 있지 않다면 활성 패널의 선택 항목만 사용합니다.

각 패널은 다음 상태를 독립적으로 관리합니다.

- 현재 폴더와 뒤로/앞으로 탐색 기록
- 정렬 순서
- 선택한 행
- 현재 세션에서 다시 방문한 폴더의 선택 및 스크롤 위치
- 파일명 필터

주요 탐색 및 파일 명령은 다음과 같습니다.

| 동작 | 단축키 |
| --- | --- |
| 선택 항목 열기 | **Command-O** |
| 선택 항목 하나 이름 변경 | **Return** 또는 **F2** |
| 선택 항목 일괄 이름 변경 (현재 소스 빌드) | **Command-Control-R** |
| 새 폴더 | **Command-Shift-N** |
| 복사 및 붙여넣기 | **Command-C**, **Command-V** |
| 뒤로 및 앞으로 | **Command-[**, **Command-]** |
| 상위 폴더 | **Command-Up Arrow** |
| 위치 편집 | **Command-L** |
| 확인 후 휴지통으로 이동 | **Delete** |
| 즉시 휴지통으로 이동 | **Command-Delete** |

행을 더블 클릭하거나 **Command-O**를 누르거나 컨텍스트 메뉴에서 **Open**을
선택해 항목을 열 수 있습니다. 일반 폴더는 현재 패널에서 이동하고, 파일과
응용 프로그램·문서 패키지는 macOS를 통해 엽니다.

현재 선택이나 편집 상태에서 안전하지 않은 명령은 비활성화됩니다. 이름, 위치,
필터를 편집할 때는 Return, Space, Escape, Delete가 일반 텍스트 편집 동작을
우선합니다.

### 패널별 필터

**Command-F**를 누르면 활성 패널에 필터가 열립니다. 현재 폴더에 이미 불러온
항목의 파일명만 검색합니다. 즉시 동작하지만 재귀 검색이나 파일 내용 검색을
하지 않으며 온라인 전용 파일을 다운로드하지 않습니다. 각 패널은 자체 필터와
결과 개수를 가집니다.

재귀 검색, 메타데이터 조건, 검색 조건 저장 또는 더 넓은 결과 집합에 대한 작업이
필요하면 Smart Search를 사용하세요.

## Smart Search와 한글 초성 검색

**Command-Shift-F**를 누르면 활성 패널의 현재 폴더를 시작점으로 Smart Search가
열립니다. Smart Search는 파일명과 상대 경로를 재귀적으로 검사합니다.

### 검색어 일치 방식

- 일반 문자열은 지역화된 대소문자 무시 방식으로 비교합니다.
- 한글 초성 검색을 지원합니다. 예를 들어 `ㅍㄱ`는 `파일관리`와 일치할
  수 있습니다.
- 혼합 입력은 모두 만족해야 하는 절로 나뉩니다. `ㅍㄱ report`는 한글 초성
  조건과 일반 문자열 `report` 조건을 모두 만족해야 합니다.
- 비어 있거나 잘못 조합된 필터는 제한 없는 파일 변경 작업을 시작하지 않습니다.

### 메타데이터 필터

다음 조건으로 결과를 제한할 수 있습니다.

- 파일 또는 폴더
- 하나 이상의 파일 확장자
- 최솟값과 최댓값을 포함하는 크기 범위
- 시작일과 종료일을 포함하는 수정 날짜 범위

검색은 이름, 상대 경로 및 일반 파일시스템 또는 File Provider 메타데이터를
읽습니다. 파일 내용 검색이 아니며 background index를 유지하지 않습니다.

### 저장된 검색

검색어와 필터를 저장하고, 다시 열고, 이름을 바꾸거나 삭제할 수 있습니다.
저장된 검색은 듀얼 패널 작업 공간과 별도의 저장 레코드를 사용합니다. 따라서
저장된 검색 데이터가 손상되어도 안전하게 빈 상태로 복구되며 패널 배치를
변경하지 않습니다.

### 검색 결과 작업과 변경된 항목 거부

결과에서 Quick Look, Finder에 표시, 반대쪽 패널에서 열기, 반대쪽 패널로 복사
또는 이동, 휴지통으로 이동을 실행할 수 있습니다. 결과는 검색 시점에 캡처한
항목의 동일성을 유지합니다. Pengrid는 모든 작업 직전에 현재 항목이 같은
대상인지 확인합니다. 항목이 교체되었다면 **“Item changed. Search again.”**을
표시하고 작업을 거부합니다.

복사, 이동 및 휴지통 작업은 파일 작업 센터에 제출됩니다. 일반 파일 패널에서
시작한 작업과 동일한 큐, 진행률, 취소, 복구 및 동일성 규칙을 사용합니다.

## Space 폴더 미리보기와 시스템 Quick Look

활성 패널에 선택 항목이 있을 때 **Space**를 누릅니다.

| 선택 항목 | 미리보기 방식 |
| --- | --- |
| 일반 폴더이며 패키지가 아닌 항목 정확히 하나 | Pengrid 폴더 내용 미리보기 |
| 파일, 패키지 또는 심볼릭 링크 | 시스템 Quick Look |
| 여러 항목 | 시스템 Quick Look |

폴더 내용 미리보기는 읽기 전용입니다. 바로 아래 한 단계의 항목만 Name, Kind,
Size, Modified 메타데이터와 함께 보여줍니다. 패널의 기본 표시 정책을 따르므로
숨김 항목도 포함됩니다. 하위 항목 열기, 탐색, 이름 변경, 전송, 압축 또는
휴지통 작업은 제공하지 않습니다.

미리보기는 목록을 읽기 전에 선택한 폴더의 동일성을 캡처합니다. 선택과 폴더
동일성이 여전히 유효할 때만 정렬된 스냅샷 하나를 게시합니다. 미리보기를 닫거나
선택을 바꾸면 이전 작업을 취소하므로 늦게 도착한 행이 새 미리보기를 덮어쓸 수
없습니다.

클라우드 폴더에서는 no-follow 디스크립터를 통해 디렉터리 항목 메타데이터만
읽으며 콘텐츠 materializer에 하위 파일 다운로드를 요청하지 않습니다. File
Provider가 로컬에 충분한 메타데이터를 제공하지 않으면
**“Folder contents are unavailable without downloading.”**이라고 표시합니다.

Space를 다시 누르거나 Escape를 누르면 현재 미리보기가 닫힙니다. 시스템 Quick
Look 패널이 열린 동안 선택을 바꾸면 최초 선택과 같은 동일성 및 클라우드
materialization 검사를 거쳐 패널이 갱신됩니다.

## 안전한 파일 작업 센터

복사, 이동, 휴지통, 새 폴더, 이름 변경, 압축, 압축 해제 및 되돌리기는 하나의
단일 작업자 변경 큐에서 조정됩니다. 단일 작업자는 두 변경 작업이 동시에 같은
대상을 교체하는 경쟁을 방지합니다.

### 캡처된 작업 의도와 큐 순서

작업을 제출하면 Pengrid는 대기 전에 관련 원본과 대상의 동일성을 캡처합니다.
대기 작업은 선입선출 순서로 시작하며 시작 전에는 더 앞이나 뒤로 이동할 수
있습니다. 대기 중 원본이 교체되거나 대상 루트가 바뀌면 교체된 항목에 작업하지
않고 안전하게 실패합니다.

### 일시 정지와 재개

일시 정지는 협력 방식입니다. 파일 항목 사이 또는 압축 단계 사이의 다음 안전한
체크포인트에서 적용됩니다. 이미 압축이나 해제를 수행 중인 네이티브 `ditto`
또는 `tar` 프로세스를 강제로 중지하지 않습니다. 일시 정지 요청을 기록하고
제어가 안전한 경계로 돌아왔을 때 적용합니다.

### 취소, 정리 및 복구 검토

대기 작업을 취소하면 파일을 변경하기 전에 큐에서 제거합니다. 실행 중인 작업을
취소하면 현재 작업의 중지를 요청하고, 롤백 또는 소유한 임시 파일 정리를
마친 다음에 다음 작업을 시작합니다.

남은 항목이 Pengrid 소유이며 안전하게 제거할 수 있는지 증명하지 못하면 삭제하지
않고 검토할 수 있도록 보존합니다. 자동 큐 진행을 중단하고 작업 센터에 복구가
필요할 수 있음을 표시합니다. 사용자가 **Continue Queue**를 선택해야 대기 작업을
재개할 수 있습니다. 취소를 성공처럼 보이게 만들기 위해 검증하지 않은 대체
항목을 삭제하지 않습니다.

### 최근 기록과 개인정보 보호

작업 센터는 현재 앱 세션에서 완료된 최신 작업 100개를 보관합니다. 기록은
디스크에 저장되지 않습니다. 행과 접근성 레이블에는 절대 상위 경로 대신 항목
이름과 안전한 요약을 사용합니다.

### 재시도

재시도는 원래 캡처한 작업 의도로 새 시도를 만듭니다. 전체 의도를 다시 실행해도
이미 성공한 항목을 중복 처리하지 않는 경우에만 제공됩니다. 일부 항목만 성공한
여러 항목 작업, Storage Inspector 정리 및 Undo는 무조건 재시도하지 않습니다.

### 보수적인 되돌리기

Pengrid가 직접 만든 변경이 그대로 유지된 경우에만 Undo를 제공합니다.

- 이동, 이름 변경 및 휴지통 복원은 변경 작업이 만든 대상이 기록된 동일성을
  유지하고 원래 경로가 비어 있어야 합니다.
- 새 폴더, 복사본, 압축 파일 또는 압축 해제 트리를 제거하려면 변경 작업이 만든
  정확한 동일성과 전체 no-follow 지문이 바뀌지 않아야 합니다.
- 대체 항목 충돌, 내용 변경, 누락된 항목, 사용 중인 복원 경로 또는 불확실한
  소유권이 있으면 Undo를 비활성화하거나 거부합니다.

Undo는 나중에 생긴 항목을 덮어쓰거나 수정된 결과물을 제거하지 않습니다.

## 미리보기 우선 일괄 이름 변경 (현재 소스 빌드)

한 패널에서 완전히 로드된 행을 두 개 이상 선택한 뒤 **File Operations > Batch
Rename…**, **Command-Control-R** 또는 파일 행 컨텍스트 메뉴의 **Batch
Rename…**을 사용합니다. 명령은 활성 패널의 선택만 실제 표에 보이는 순서대로
캡처합니다. 인라인 텍스트 편집 중이거나 다른 배타적 파일 작업이 실행 중이면
비활성화됩니다.

### 규칙과 확장자 보존

시트는 하위 폴더를 재귀적으로 처리하지 않는 네 가지 규칙을 제공합니다.

- **Find & Replace**는 일반 문자열을 대소문자 구분 또는 지역화된 대소문자
  무시 방식으로 바꿉니다.
- **Prefix**는 편집 가능한 파일명 줄기 앞에 문자열을 넣습니다.
- **Suffix**는 편집 가능한 파일명 줄기 뒤에 문자열을 넣습니다.
- **Sequence**는 캡처한 표 순서에 따라 기본 이름과 번호를 만들며 시작 번호와
  0 채움 자릿수를 지정할 수 있습니다.

규칙은 이름만 편집하며 경로나 파일 내용은 바꾸지 않습니다. 일반 파일은 마지막
확장자를, 패키지는 패키지 확장자를, 알려진 압축 이름은 `.tar.gz`, `.tar.bz2`,
`.tar.xz` 등을 포함한 정확한 복합 확장자를 보존합니다. 일반 폴더는 이름 전체를
편집 대상으로 보고, 두 번째 점이 없는 점 파일도 이름 전체를 대상으로 봅니다.

정규식, 하위 폴더 재귀 이름 변경, 확장자 직접 편집, 대소문자 정책 강제 변경 및
행마다 다른 사용자 지정 이름은 의도적으로 지원하지 않습니다.

### 미리보기와 기능 허용 조건

각 선택 행에는 이전 이름, 제안한 이름 및 상태가 표시됩니다. 두 항목 미만, 서로
다른 상위 폴더, 잘못 생성된 이름, 제안 이름 중복, 선택하지 않은 형제 항목과의
충돌 또는 모든 행이 변경 없음인 계획은 제출할 수 없습니다. 다른 선택 원본이
현재 사용 중인 이름은 사용할 수 있으므로 이름 교환과 더 긴 순환 변경이
가능합니다.

가장 최신의 비동기 미리보기만 결과를 게시하고 오래된 세대는 폐기합니다. 자동
회귀 검증은 10,000개 행 미리보기가 5초 이내에 끝나도록 요구합니다. 이 5초는
큰 성능 퇴행을 잡는 상한이며 일반 미리보기가 그만큼 걸려도 된다는 목표가
아닙니다.

쓰기 가능한 로컬 폴더를 지원합니다. 등록된 File Provider 위치는 발견 정보가
로컬 파일 작업 기능을 제공하고 선택한 디렉터리가 실시간 파일시스템 쓰기 가능
검사를 통과할 때만 지원합니다. 읽기 전용 provider는 거부하고, 등록되지 않은
`~/Library/CloudStorage` 하위 경로는 기능을 알 수 없으므로 fail closed
처리합니다. Pengrid는 캡처한 요청에 대해 scoped access를 한 번만 획득하며,
거부되면 반복해서 권한을 묻지 않고 오류 하나를 표시합니다.

### 트랜잭션, 진행 단계, 취소, 재시도 및 되돌리기

미리보기가 실행 가능할 때만 Return을 누르거나 **Rename N Items**를 선택할 수
있습니다. 제출 계획은 불변이며 작업 센터로 전달될 때까지 필드를 잠급니다. 첫
변경 전에 상위 폴더, 모든 원본의 동일성, 파일시스템 이름 비교 정책, 형제 이름
및 최종 대상을 다시 확인합니다.

실행은 같은 폴더에서 직렬로 처리합니다. 변경할 원본을 먼저 예약된 임시 이름으로
옮긴 뒤 최종 이름으로 게시합니다. 이 2단계 트랜잭션은 내용을 덮어쓰지 않고
`A -> B, B -> A` 교환 및 더 긴 순환을 지원합니다. 작업 센터는 상위 경로를
노출하지 않는 제한된 항목 수와 함께 **Staging names**, **Publishing names**,
필요한 경우 **Rolling back names** 단계를 표시합니다.

첫 변경 뒤 취소하면 의존 순서에 맞춰 롤백을 시도합니다. 모든 최종 이름이
존재하고 예약 임시 이름이 하나도 남지 않아야 성공입니다. 복구를 증명할 수 없으면
불확실한 항목을 삭제하지 않고 복구 검토 상태로 표시하며 큐를 중지합니다.

재시도는 정확히 캡처한 계획으로 새 시도를 만들고 모든 사전 검사를 다시
실행합니다. 되돌리기는 같은 2단계 엔진으로 전체 트랜잭션을 역방향 실행하지만,
모든 최종 항목의 기록된 동일성과 지문이 유지되고 모든 원래 이름을 사용할 수
있을 때만 허용합니다. 변경·교체된 결과, 누락된 항목 및 새로 차지된 원래 이름이
있으면 되돌리기를 비활성화하거나 거부합니다.

## 압축 생성, 해제 및 진행률

**File Operations** 메뉴 또는 파일 행의 컨텍스트 메뉴에서 압축 파일을 만들거나
풀 수 있습니다.

### 지원 형식

| 형식 | 생성 확장자 | 압축 해제 시 인식하는 확장자 |
| --- | --- | --- |
| ZIP | `.zip` | `.zip` |
| TAR | `.tar` | `.tar` |
| TAR.GZ | `.tar.gz` | `.tar.gz`, `.tgz` |
| TAR.BZ2 | `.tar.bz2` | `.tar.bz2`, `.tbz`, `.tbz2` |
| TAR.XZ | `.tar.xz` | `.tar.xz`, `.txz` |

새 TAR 계열 파일은 긴 표준 확장자를 사용합니다. 짧은 별칭은 압축을 풀 때
입력 형식으로 인식합니다.

### 원본 처리와 충돌 안전성

단일 파일, 폴더, 패키지 및 선택한 심볼릭 링크를 압축할 수 있습니다. 선택한
심볼릭 링크는 링크로 보존하며 대상 파일의 바이트로 몰래 대체하지 않습니다.
장치 노드, 소켓, FIFO 같은 지원하지 않는 특수 파일시스템 항목은 거부합니다.

압축 및 압축 해제 대상은 기존 항목을 덮어쓰지 않습니다. 시작 전에 사용 가능한
이름을 선택하고 배타적으로 결과를 게시합니다. 다른 프로세스가 게시 직전에
대상을 만들면 교체하지 않고 안전한 충돌 실패 또는 새로운 사용 가능 이름
결정을 수행합니다.

### 제한된 병렬 준비

여러 원본을 선택하면 먼저 비공개 통합 스테이징 디렉터리로 복사합니다. 이 준비
단계만 병렬로 실행합니다. 작업자 수는 다음 값 중 가장 작은 값입니다.

- 4
- 사용 가능한 프로세서 수
- 선택한 원본 수

네이티브 압축 명령은 하나의 로컬 프로세스로 유지됩니다. 압축 해제 역시 하나의
네이티브 프로세스를 사용합니다. 원본 준비만 병렬인데 압축 자체가 병렬이라고
표현하지 않습니다.

### 진행 단계

- **Preparing files, X of Y**는 최상위 스테이징 항목 수를 정확히 표시합니다.
- **Encoding archive** 또는 대응하는 압축 해제 단계는 진행률 미정으로
  표시합니다. macOS `ditto`와 `tar`가 형식 전체에 적용할 수 있는 신뢰할
  만한 바이트 총량을 제공하지 않기 때문입니다.
- **Finishing archive**는 스테이징 결과를 검증한 뒤 대상을 배타적으로 게시하는
  동안에만 표시됩니다.

중간 준비 업데이트는 초당 10회로 제한하지만 단계의 시작과 완료 경계는 항상
전달합니다. 전체 작업 동안 Cancel을 사용할 수 있습니다.

### 암호로 보호된 ZIP 동작

소스 빌드에서 암호 보호 ZIP을 만들 때는 **AES-256만** 사용합니다. 현재 안전
정책을 통과하고 압축 방식이 Store 또는 Deflate인 항목은 AES-128, AES-192,
AES-256 및 ZipCrypto를 읽을 수 있습니다. ZIP 파일명, 크기, 시각 및 중앙
디렉터리 메타데이터는 보입니다. 암호화는 파일명을 숨기지 않습니다.

Pengrid는 현재 요청 동안에만 암호를 보관합니다. 암호를 저장하거나 복구하거나
노출하지 않습니다. 암호가 틀리거나 인증에 실패하면 보관한 값을 재사용하지
않고 새 입력 창을 다시 표시합니다.

위험한 경로, traversal, 잘못된 구조 및 설정된 크기나 항목 제한을 넘는 압축
파일은 fail closed로 거부합니다. 남은 임시 항목의 소유권을 증명할 수 없으면
복구 검토를 위해 보존하고 큐 진행을 멈추며, 검토 후 사용자가 명시적으로
계속해야 합니다. 리소스 포크, ACL 및 확장 속성의 왕복은 보장하지 않습니다.
Finder와 Archive Utility는 AES ZIP을 열지 못할 수 있습니다. 저장소의 타사
호환성 설명은 커밋된 자동 fixture로 제한되며 실제 Finder, Archive Utility,
Windows 또는 WinZip 결과를 뜻하지 않습니다.

이 소스 기능은 7z, RAR 또는 암호로 보호된 TAR을 지원하지 않습니다. Developer
ID 서명과 공증도 지원되는 패키지 경계 밖에 있습니다.

## macOS File Provider를 통한 Google Drive와 OneDrive

Pengrid는 Google Drive 또는 OneDrive가 macOS에 등록한 provider root를
발견합니다. 이는 File Provider 통합이며 Google 또는 Microsoft OAuth/API
직접 연동이 아닙니다. Pengrid는 해당 계정 자격 증명을 요구하지 않습니다.

작업은 두 부류로 나뉩니다.

- Smart Search와 폴더 미리보기는 현재 공개된 메타데이터를 사용하며 온라인 전용
  하위 항목의 파일 내용을 의도적으로 읽거나 내려받지 않습니다.
- 열기, Quick Look, 복사, 이동, 내용 비교, 압축 및 압축 해제에는 실제 바이트가
  필요할 수 있습니다. 이 경우 macOS File Provider가 로컬 작업을 계속하기 전에
  필요한 원본을 다운로드할 수 있습니다.

provider는 로컬에 없는 메타데이터를 생략할 수 있습니다. Pengrid는 결과를
지어내지 않고 사용할 수 없음 또는 실패 상태를 표시합니다. provider 작업은
필요한 기간에만 scoped access를 유지하며 로컬 파일과 같은 동일성 검사를
사용합니다.

## 디렉터리 비교

**Compare > Compare Folders**를 선택하면 두 패널의 루트를 비교합니다. 상대
경로를 기준으로 항목을 정렬하고 한쪽에만 있는 항목, 메타데이터 차이, 이름
충돌 및 내용 검증이 필요한 항목을 표시합니다.

**Verify Selected Contents**와 **Verify All Contents**는 요청한 후보에 대해서만
체크섬을 계산합니다. 복사는 왼쪽에서 오른쪽 또는 오른쪽에서 왼쪽 방향을
명시적으로 선택합니다. 이동은 확인 시트를 거쳐야 합니다.

비교 중 두 루트의 변경을 감시합니다. 루트 교체, 파일시스템 이벤트 유실 또는
항목 동일성 변경이 감지되면 오래된 결과를 무효화하고 영향을 받은 데이터를
다시 조정할 때까지 안전하지 않은 작업을 비활성화합니다. 재귀 목록에서 심볼릭
링크와 패키지는 내부를 따라가지 않고 불투명한 항목으로 취급합니다.

## Storage Inspector

**Storage > Enter Storage Inspector**를 선택한 뒤 로컬 폴더 또는 직접 연결된
볼륨을 선택하고 스캔을 시작합니다. 전체 트리가 끝날 때까지 기다리지 않고
결과를 점진적으로 표시합니다.

Storage Inspector는 다음 항목을 보여줄 수 있습니다.

- 큰 파일
- 오랫동안 수정되지 않은 파일
- 전체 내용 체크섬으로 검증한 정확히 같은 중복 파일

중복 파일 정리는 최소 한 개의 복사본을 남기고, 명시적으로 검토하고 동일성을
다시 확인한 선택 항목만 macOS 휴지통으로 보냅니다. 파일을 영구 삭제하지
않습니다.

Storage Inspector는 background index를 실행하거나 심볼릭 링크 또는 패키지를
따라가지 않으며 네트워크 루트 또는 클라우드 전용 콘텐츠를 분석하지 않습니다.
루트 교체, 연결 해제, 읽을 수 없는 항목 및 취소를 보고하며 다른 마운트 위치로
몰래 전환하지 않습니다.

## 접근성, 키보드 접근 및 개인정보 보호

Pengrid는 패널, 검색 컨트롤, 미리보기 상태, 압축 단계, 작업 센터 컨트롤,
비교 행 및 Storage Inspector 결과에 안정적인 레이블을 제공합니다. VoiceOver는
작업 행에서 절대 상위 경로를 읽지 않으면서 동작과 현재 상태를 식별할 수
있습니다. 동작 줄이기는 상태 변경을 유지하면서 불필요한 애니메이션을
비활성화합니다.

메뉴 명령은 Full Keyboard Access로 접근할 수 있으며 텍스트 편집기는 표준 편집
동작을 유지합니다. 자동 테스트는 식별자, 레이블, 순서 및 개인정보를 노출하지
않는 상태 문구를 검증합니다. 후보별 수동 VoiceOver 및 키보드 검사는 별도
검증 문서에 기록됩니다.

## 현재 제한 사항

Developer Preview 5와 현재 소스 트리는 다음 기능을 의도적으로 제공하지 않습니다.

- Intel Mac 또는 macOS 14 이하 지원
- Developer ID 서명 또는 Apple notarization
- Google Drive 또는 OneDrive OAuth/API 직접 클라이언트
- background index 또는 file-content search
- 모든 온라인 전용 provider 항목에 대한 메타데이터 보장
- 네이티브 압축 도구의 신뢰할 수 있는 바이트 단위 진행률
- 7z, RAR 또는 암호로 보호된 TAR
- 영구 삭제
- 소유권 또는 동일성을 증명할 수 없는 항목의 자동 제거
- 일괄 이름 변경 정규식, 하위 폴더 재귀 변경, 확장자 직접 편집 또는 행별 사용자
  지정 이름

후보별 검증 증거와 아직 남아 있는 수동 확인은
[릴리스 및 패키징](release.ko.md)과
[검증 문서](verification/)에서 확인할 수 있습니다.
